## Cycle 5 Task: ACTIVE — CRITICAL PATH
**Investigation:** What is the maximum particle density for real-time tracking?

**Critical Questions:**
1. At N=100 particles, what is compute time for:
   - Detection-to-track association (Hungarian: O(N³), approximation: O(N²), greedy: O(N log N))
   - Kalman filter update per particle (parallelizable on GPU)
   - Track birth/death decisions

2. At N=500 particles, does any algorithmic strategy achieve <10ms tracking?
   - If yes: What hardware is required?
   - If no: What density is the practical limit?

3. Can tracking run in parallel with detection (pipelined) or must it be sequential?
   - Pipeline: Frame N detection overlaps with Frame N-1 tracking
   - Sequential: Detection must complete before tracking starts (bad for latency)

**Mathematical Framework:**
- Detection output: (x, y, z, confidence) per particle per camera
- Correspondence: Match current detections to existing tracks
- Motion model: Brownian + velocity persistence (air currents)
- Identity preservation: 95% over 5-frame window

**Algorithm Options to Benchmark:**
1. **Greedy nearest-neighbor:** O(N²) worst case, fast in practice for sparse
2. **Approximate Hungarian (Jonker-Volgenant):** O(N³) worst, O(N²) typical
3. **GPU brute-force:** Parallel O(N²) acceptable if N<200

**Deliverable:** 
1. Tracking compute time function: f(N_particles, algorithm, hardware)
2. Maximum N for <10ms tracking on RTX 4090
3. Pipeline recommendation: Overlapped vs Sequential detection+tracking
